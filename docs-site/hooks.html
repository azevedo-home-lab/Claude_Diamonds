01

What a hook is

Source: Hooks reference.

Anthropic's own definition: hooks are "user-defined shell commands, HTTP endpoints, or LLM prompts that execute automatically at specific points in Claude Code's lifecycle." That's the whole idea. A hook doesn't wait to be asked — it fires because a lifecycle point was reached, not because Claude called a tool named "hook." Claude Code has more than twenty distinct hook events, grouped by how often they fire: once per session, once per turn, or once per tool call inside the agentic loop covered on the loops page.

02

Where hooks fire in the loop

Mapped onto the same mechanical loop from the loops lesson: receive prompt, evaluate, execute tools, repeat, return result.

UserPromptSubmit fires before Claude even sees your prompt — outside the agentic loop entirely. Once the loop starts, PreToolUse fires immediately before each tool call executes, and PostToolUse immediately after it succeeds — both fire on every single tool call, every turn, for as long as the loop runs. When Claude finally produces a turn with no tool calls and the loop ends, Stop fires once. SessionStart and SessionEnd sit outside all of that, firing once when the session begins and once when it terminates.

PreToolUse and PostToolUse fire on every tool call, every turn, for as long as the agentic loop runs. Stop fires exactly once, the moment the loop ends.

03

Four events worth knowing

Claude Code defines more than twenty hook events in total. These four cover the cases most lessons reach for first.

EventFiresCommonly used for
PreToolUseBefore a tool call executesSecurity policy, input validation, blocking destructive commands
PostToolUseAfter a tool call succeedsValidation, logging, redacting or annotating tool output
StopWhen Claude finishes a turn with no further tool callsChecking the response, injecting feedback to continue the conversation
SessionStartOnce, when a session begins or resumesEnvironment setup, injecting context Claude should see from the start

The rest cover narrower cases — subagents starting or stopping, a watched file changing on disk, a worktree being created, an MCP server asking the user for input. Same mechanism throughout: a fixed lifecycle point, a command or endpoint that runs automatically.

04

Blocking a tool call

Two ways to signal a block, and one exit code that matters more than the rest.

A PreToolUse hook can stop a tool call before it ever runs. It signals that two ways: exiting with status code 2, or returning JSON with hookSpecificOutput.permissionDecision: "deny". Anthropic's documentation is explicit about the exit-code convention: "Claude Code treats exit code 1 as a non-blocking error and proceeds with the action, even though 1 is the conventional Unix failure code. If your hook is meant to enforce a policy, use exit 2."

Blocking isn't silent. Anthropic states plainly what happens next: "Claude Code reads the JSON decision, blocks the tool call, and shows Claude the reason." With exit code 2, that reason is whatever the hook wrote to stderr. With the JSON form, it's the permissionDecisionReason field. Either way, the tool never runs, and Claude sees why — it can explain the block to you, or try a different approach, rather than silently retrying the same blocked call.

05

A worked example

Anthropic's own example: a PreToolUse hook guarding against rm -rf.

The hook matches on the Bash tool, inspects the command Claude is about to run, and decides whether to let it through.

StepWhat happens
1Claude decides to call Bash with a command, as part of a turn
2PreToolUse fires before execution; the hook reads tool_input.command from its JSON input
3If the command matches rm -rf, the hook returns permissionDecision: "deny" with a reason; otherwise it exits 0 and normal permission handling applies
4On deny, the tool never runs — Claude receives the permissionDecisionReason text and continues the turn knowing why
A hook is a policy layer, not the permission system itself. Anthropic's own guidance: "To enforce a hard allow or deny, use the permission system rather than a hook." Hooks are for logic a static permission rule can't express — inspecting the actual command text, checking external state, deciding case by case.
