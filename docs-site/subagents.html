Subagents

A subagent is a second Claude, doing a piece of work in a context window of its own. What it starts with, what it can't see, and what makes it back to you when it's done — all of it traces to one page in Anthropic's own documentation.

1 Anthropic source 7 sections Source: Create custom subagents
01

Why a subagent exists

Source: Create custom subagents.

Anthropic's own framing: use a subagent when a side task would flood your main conversation with search results, logs, or file contents you won't reference again. The subagent does that work in its own context and returns only the summary. Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions. When Claude encounters a task that matches a subagent's description, it delegates to that subagent, which works independently and returns results.

02

A fresh context window

Source: Manage subagent context.

Anthropic's own wording is direct: "Each subagent starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read." Claude composes a delegation message that summarizes the task, and the subagent works from that message outward — not from anything already in the parent's transcript.

The subagent's window starts empty except for the delegation message — the parent's accumulated history stays behind.

03

What a subagent inherits at spawn

Source: What loads at startup.

A non-fork subagent's initial context contains a specific, named set of things. Its own system prompt — the agent's own prompt plus environment details Claude Code appends, not the full Claude Code system prompt. The task message — the delegation prompt Claude writes when it hands off the work. And the full CLAUDE.md hierarchy the main conversation loads: ~/.claude/CLAUDE.md, project rules, CLAUDE.local.md, and managed policy files.

Loads at startupWhat it is
System promptThe subagent's own prompt, plus environment details — never the parent's full system prompt
Task messageThe delegation prompt Claude writes when handing off the work
CLAUDE.md hierarchyEvery level the parent conversation loads: user, project, local, and managed policy files
Git statusA snapshot taken at the start of the parent session, when the working directory is a git repo
Preloaded skillsFull content of any skill named in the subagent's skills field

Two built-in subagents, Explore and Plan, are named exceptions: they skip CLAUDE.md and git status to keep research fast and inexpensive.

04

What a subagent does not inherit

Source: What loads at startup. The gaps matter as much as the list above.

Three things from the parent conversation never reach a non-fork subagent. Your output style doesn't shape its responses, since the subagent runs its own system prompt. The parent's auto memory isn't loaded — a subagent gets persistent memory of its own only through its memory field. And its context window size is set by its own model, not the parent's: delegating to a smaller model gives that subagent the smaller window that model has.

05

What comes back to the parent

Source: Create custom subagents, isolating high-volume operations.

When a subagent finishes, Claude sees only its final response — not the search results, file contents, or intermediate tool calls that produced it. Anthropic states the payoff directly: running tests, fetching documentation, or processing log files can consume significant context; delegating that work to a subagent keeps the verbose output in the subagent's own context, while only the relevant summary returns to the main conversation. That gap between what the subagent processed and what it hands back is the entire reason subagents save context.

Not free, though. Anthropic's own warning: when subagents complete, their results return to your main conversation, and running many subagents that each return detailed results can still consume significant context. Delegating helps because a subagent's working context stays contained — not because its final answer costs nothing.

07

When delegating actually helps

Source: Choose between subagents and main conversation.

Anthropic draws the line plainly. Stay in the main conversation when the task needs frequent back-and-forth, when planning, implementation, and testing share significant context, when the change is quick and targeted, or when latency matters — subagents start fresh and may need time to gather context. Reach for a subagent when the task produces verbose output you don't need in your main context, when you want to enforce tool restrictions or permissions, or when the work is self-contained and can return as a summary.

The fresh context window is the whole trade: a subagent costs you the latency of starting cold, and buys back a main conversation that never had to hold what it found along the way.
