## The model

Five layers, top to bottom. Each layer answers one question:

1. **Vision / Mission** — Where are we going, and why does it matter?
   The fixed point. Changes rarely, if ever.
2. **Strategy** — How will we get there? Explicit trade-offs: where to
   play, how to win. A strategy that excludes nothing is not a strategy.
3. **Objectives (and Key Results)** — What is important right now?
   Outcomes (what changes for whom), never outputs (what we build).
4. **Opportunities (and Solutions)** — What actions are we taking?
   Customer needs and pains worth addressing; solutions come second
   because they serve specific opportunities.
5. **Principles** — How do we make everyday choices without escalating?
   Best written as trade-offs: "X *even over* Y."

## The connective test (the part that does the work)

- Reading **down**, each layer answers *how* the layer above will be
  achieved.
- Reading **up**, each layer answers *why* this work matters.
- The **how/why test**: walk any item up the stack. The first link that
  cannot be stated in one sentence is exactly where the missing work is.

## Mapping to this method's stack

The front diamond phrases the per-product stack as
**Vision → North Star + input metrics → Strategy and bets → Initiatives**.
The mapping to Eriksson is: North Star + input metrics play the Objectives
layer (standing outcome metric instead of quarterly OKRs); bets play the
Opportunities layer at portfolio grain; Initiatives are solution-level.
Principles have no per-product layer here — the project instructions and
this method are the principles layer, shared across products. The order of
reasoning is Eriksson's: no initiative is justified by pointing sideways
(at a competitor, a technology, an idea's elegance) — only by pointing up.
