Turns, the agentic loop, and loop patterns

Three words that get used interchangeably and shouldn't be. What each one means, how they nest, and how Anthropic itself describes the machinery twice — once as a concept, once as a mechanism.

01

Three words people mix up

The payload, first, before the mechanics.

A turn is one round trip: Claude produces output, the harness executes any tool calls in it, and the results feed back to Claude automatically. The agentic loop is the cycle of turns that runs inside a single prompt — it starts when you submit, and ends when Claude responds with no tool calls. A loop pattern is a layer outside all of that: something that decides when to send another prompt in the first place. /goal, /loop, and /schedule are loop patterns. They don't touch the engine — they just decide when to start the next turn.

Turns nest inside one agentic loop; a loop pattern decides when a new prompt — and a new agentic loop — begins.

02

The loop, conceptually

Source: How Claude Code works.

Anthropic's conceptual description of the agentic loop names three phases: gather context, take action, and verify results. These blend together rather than running in strict sequence — Claude uses tools throughout, whether searching files to understand code, editing to make changes, or running tests to check its own work. A simple question might only need the first phase. A bug fix cycles through all three repeatedly. You're part of this loop too: you can interrupt at any point to steer Claude, add context, or ask for a different approach.

The three phases blend and repeat until the task is complete. You can interrupt at any point.

03

The loop, mechanically

Source: How the agent loop works. Same machine, viewed closer.

Anthropic's mechanical description names five steps: receive prompt (Claude gets your prompt plus system prompt, tool definitions, and history), evaluate and respond (Claude decides how to proceed — text, tool calls, or both), execute tools (the harness runs each requested tool and collects results), repeat (steps two and three cycle — each full cycle is one turn), and return result (a final response with no tool calls ends the loop). This is not a competing model of the loop — it's the same three-phase cycle, described at the level of what actually executes.

Each evaluate→execute cycle is one turn. The loop ends the first time evaluation produces no tool calls.

04

What one turn actually is

Anthropic's own worked example: "Fix the failing tests in auth.ts."

A turn is one round trip: Claude produces output that may include tool calls, the harness runs them, and the results feed back to Claude — all without returning control to you. Turns continue until Claude produces output with no tool calls. Here is Anthropic's own four-turn trace of that prompt.

TurnClaude didWhat came back
1Called Bash to run npm testThree failures
2Called Read on auth.ts and auth.test.tsFile contents
3Called Edit to fix auth.ts, then Bash to re-run testsAll three tests pass
4 (final)Text-only response, no tool calls"Fixed the auth bug, all three tests pass now."

Four turns total: three carried tool calls, one was text-only and ended the loop.

05

Bounding the loop

Without a limit, the loop runs until Claude decides it's done — fine for a scoped task, risky for "improve this codebase."

The SDK exposes two caps. max_turns limits tool-use round trips only — a text-only turn doesn't count against it. max_budget_usd caps spend, and it covers subagents too: their cost counts toward the parent's total, and once the cap is hit, spawning another subagent fails outright.

When a run ends, a result message reports which of five ways it ended:

ResultWhat happened
successClaude finished the task normally
error_max_turnsHit the turn limit before finishing
error_max_budget_usdHit the budget limit before finishing
error_during_executionAn error interrupted the loop — an API failure or a cancelled request
error_max_structured_output_retriesNo valid structured output within the retry limit
06

The four loop patterns

Source: Loop engineering: getting started with loops. This is the layer outside the agentic loop — what decides when a new prompt starts.

Each pattern moves further from a person triggering each run by hand.

PatternTriggerStops whenBest for
turn-basedA user promptClaude decides the task is complete, or needs more contextShorter tasks outside a regular process
goal-based · /goalA manual, real-time prompt naming a conditionThe goal is achieved, or max turns is reachedTasks with a verifiable exit criterion
time-based · /loop, /scheduleA fixed time intervalUser cancellation, or the work is doneRecurring work; watching an external system
proactiveAn event or a schedule, no person in the loopEach individual task exits once its own goal is metWell-defined recurring work — triage, dependency upgrades

Anthropic's own example for goal-based loops: "/goal get the homepage Lighthouse score to 90+, stop after 5 tries". Proactive loops are a composition of the other three — /schedule, /goal, skills, and auto mode working together.

07

Where the human stays

A self-checking loop grades its own work. That's a real limit, and Anthropic says so directly.

Anthropic's own guidance for loop engineering: encode manual checks as skills with quantitative metrics, so Claude can verify its own work end-to-end rather than eyeballing it. And where bias matters, use a separate review agent — not the same one that did the work — to check it.

The general principle, not a pitch. A loop that grades itself is only as reliable as its own judgment. The strongest version separates the two: one loop does the work, a different, independent check decides if it's done. claude-code-workflows is one concrete example of that separation, built as an external judge/gate chain rather than a self-graded loop — worth a look if this idea is useful to you.
08

Correcting a common claim

Worth stating plainly, since it's easy to get wrong — this page did, earlier in its own drafting.

/goal is often described online as a community-authored convention: a Markdown file you drop into .claude/commands/ yourself, with no first-party backing. That undersells it. Anthropic documents /goal directly, as one of four named loop patterns, complete with its own worked example. It is Anthropic-documented behavior, not a fan-made trick that happens to work.
