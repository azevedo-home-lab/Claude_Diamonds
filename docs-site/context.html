What accumulates in Claude's context window, what happens automatically when it fills up, and two concrete ways to control what survives — all sourced from Anthropic's own documentation.

01

Three things people conflate

The payload, first, before the mechanics.

The context window is the total amount of information available to Claude during a session — it does not reset between turns, and everything accumulates: the system prompt, tool definitions, conversation history, tool inputs, and tool outputs. Compaction is what happens automatically when that window approaches its limit: Claude Code clears older tool outputs first, then summarizes remaining older history to free space. Steering is what you do to influence what a compaction keeps — writing summarization instructions into CLAUDE.md, or running /compact with a focus. None of these are the same thing, and mixing them up is why "I told it that three messages ago" is a confusing bug report rather than an expected outcome.

02

What fills the context window

Source: The context window, in the agent-loop docs.

Content that stays the same across turns — the system prompt, tool definitions, CLAUDE.md — is automatically prompt-cached, which reduces cost and latency for repeated prefixes. Conversation history is the one source that keeps growing: it accumulates every prompt, response, tool input, and tool output as a session runs. A single large file read or a verbose command output can use thousands of tokens in one turn, so longer sessions with many tool calls build up context far faster than short ones.

System prompt, CLAUDE.md, tool definitions, and skill descriptions hold roughly steady turn to turn. Conversation history is the source that keeps growing, closing the gap to the limit.

System promptEvery requestSmall fixed cost, always present
CLAUDE.md filesSession startFull content in every request, but prompt-cached — only the first request pays full cost

Skill descriptionsSession startShort summaries; full content loads only when a skill is invoked
03

Automatic compaction

Sources: Automatic compaction, in the agent-loop docs and When context fills up, in How Claude Code works.

When the context window approaches its limit, Claude Code compacts the conversation automatically, in two steps: it clears older tool outputs first, then summarizes the remaining older history if more space is still needed. Your requests and key code snippets are preserved; detailed instructions from early in the conversation may not be. This is why a persistent rule stated only once, early in a long session, can quietly stop applying — it was never re-stated, and the summary that replaced it didn't carry the specific wording forward.

The SDK emits a message with type: "system" and subtype: "compact_boundary" when this happens, so a program driving the loop can detect it. If a single file or tool output is so large that context refills immediately after each summary, Claude Code stops auto-compacting after a few attempts and shows an error instead of looping.

Older tool outputs clear first; if more space is still needed, older history is replaced with a summary. Recent turns stay intact.

04

Steering what compaction keeps

Two concrete techniques, both Anthropic-documented.

The compactor reads CLAUDE.md like any other context, so a section telling it what to preserve when summarizing works — the header name is free-form; the compactor matches on intent, not on a magic string. Because CLAUDE.md content is re-injected on every request, a rule stated there survives compaction in a way a rule stated only once in the initial prompt does not.

FileContent
CLAUDE.md# Summary instructions
When summarizing this conversation, always preserve: the current task objective and acceptance criteria, file paths that have been read or modified, test results and error messages, decisions made and the reasoning behind them.

The second technique is manual: send /compact as a prompt to trigger compaction on demand, optionally with a focus — for example /compact focus on the API changes — to steer what the resulting summary emphasizes. A third option, the PreCompact hook, runs custom logic before compaction occurs (for example, archiving the full transcript) but doesn't change what the summary itself keeps, so it's an escape hatch rather than a steering technique.

05

Keeping context efficient

Source: Keep context efficient, in the agent-loop docs.

Compaction and steering manage a window that's already filling up. These reduce how fast it fills in the first place. Subagents start with a fresh conversation and no prior message history — only their final response returns to the parent as a tool result, so the main agent's context grows by that summary, not by the full subtask transcript. Being selective with tools matters because every tool definition takes context space; scoping a subagent to the minimum set it needs keeps its window lean. MCP tool search defers tool schemas by default and loads them on demand, so idle MCP servers cost little until a specific tool is actually used. Lower effort levels reduce token usage per turn for agents that only need to read files or list directories.

Context cost by feature

Source: Understand context costs, in Extend Claude Code.

Every feature you add — CLAUDE.md, skills, MCP servers, subagents, hooks — consumes some of Claude's context, but each has a different loading strategy and a different cost.

FeatureWhen it loadsWhat loadsContext cost
CLAUDE.mdSession startFull contentEvery request
SkillsSession start + when usedDescriptions at start, full content when usedLow (descriptions every request)
MCP serversSession startTool names; full schemas on demandLow until a tool is used

Set disable-model-invocation: true in a skill's frontmatter to hide it from Claude until invoked manually — this reduces its context cost to zero for skills you only trigger yourself.
