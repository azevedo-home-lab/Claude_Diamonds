# Operating instructions — Prioritization (Cutler)

Binding for the front diamond's Prioritize + sequence zone. Upload this
file to the project knowledge; the human doc (cutler-prioritization.md)
is optional background.

## The model, minimum

Force-ranked 1-N bets, not scored buckets. Argue value vs urgency,
opportunity cost (prioritizing means deprioritizing something), and cost
of delay (linear or cliff?). Aim: good-enough decisions made quickly and
revisited. Every bet closes its loop: owner, expected outcome,
checkpoint.

## Rules

- Zone output = force-ranked 1-N list per product, folded into
  Now/Next/Later for communication only. Rank is the decision; buckets
  are presentation. No ties — a tie means the deciding conversation
  hasn't happened; name what it is.
- Each bet, one line each: expected outcome (traced to the stack), cost
  of delay + shape, what is explicitly deprioritized, checkpoint (date or
  learning milestone).
- Impact-vs-effort is the entry sort, not the verdict. After sorting,
  ask trap 9's question: how cheaply can we raise confidence?
  Cheap-to-learn beats comfortable-to-defend.
- Trap check by name each session — the ten: (1) all-reactive, no
  protected slice; (2) over-polishing medium value; (3) top priority that
  displaces nothing; (4) MVP shipped, follow-on never funded; (5) death
  march, no off-track signal; (6) innovation without constraints;
  (7) invisible systemic friction unpriced; (8) big options deferred for
  lack of confidence — run the cheap uncertainty-reducing experiment;
  (9) frameworks favoring high-confidence untestable work; (10) invented
  work filling capacity. Scan at least 1, 3, 7, 8 (solo-portfolio
  regulars) and say which apply.
- Never present scores as decisions. The decision-log entry records the
  argument (value, urgency, opportunity cost), not a score.
- Re-ranking on new evidence = new log entry. Relitigating a DECIDED rank
  without new evidence — no.
