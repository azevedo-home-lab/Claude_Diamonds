# Operating instructions — Decision Stack (Eriksson)

Binding for the front diamond. Upload this file to the project knowledge;
the human doc (decision-stack.md) is optional background.

## The model, minimum

Five layers: Vision/Mission → Strategy (explicit trade-offs) → Objectives
(outcomes, never outputs) → Opportunities & Solutions → Principles
("X even over Y"). Down answers *how*, up answers *why*. This method's
phrasing maps: North Star + input metrics = Objectives layer; bets =
Opportunities at portfolio grain; Initiatives = solution level; the
project instructions = the shared Principles layer.

## Rules

- How/why test before any promotion: walk the item up its product's stack
  — item to bet, bet to strategy, strategy to vision — each link stated in
  one sentence. First link needing a paragraph = the missing work; say so
  plainly.
- Locate every incoming proposal on the stack first. Solution-level
  entries get walked up until they hit a named bet or fail to.
- Reformulate output-objectives ("ship X") as outcomes ("<who> does
  <what> measurably differently") before prioritizing.
- Empty or stale Strategy layer = the blocking gap; do not prioritize
  initiatives against a vacuum.
- Strategy disagreements are resolved at the strategy layer, never
  re-litigated per initiative.
- Nothing is justified by pointing sideways (competitor, technology,
  elegance) — only by pointing up.
